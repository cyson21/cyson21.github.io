# 회사 실무 경력기술서의 근거와 편집 범위

2026-10-03 검토. 경력기술서는 회사별 담당 업무와 실무 판단을 설명하는 3쪽 문서다. 개인 프로젝트는 보조 링크로만 연결한다. 회사 코드·내부 URL·고객 식별 정보는 복사하지 않는다.

## 공통 원본과 확장

- 경력·기간·담당 업무·사례의 제목·문제·변경: [site.ts](../../src/data/site.ts).
- 원인·해결 선택과 이유·검증 근거·주장 한계: [career-description.ts](../../src/data/career-description.ts).
- 편집·출력 템플릿: [career.astro](../../src/pages/resume/career.astro).
- 출력: [career-description.pdf](../../public/downloads/career-description.pdf).

사례는 동일한 anchor로 공통 원본과 연결해 순서를 바꿔도 다른 설명이 붙지 않게 한다. 이력서 2쪽과 경력기술서 3쪽은 서로를 대체하지 않는다. 웹 포트폴리오의 RabbitMQ 사례는 상세 보조 근거로 유지하고 경력기술서 대표 4개에는 추가하지 않는다.

## 채용 담당자 관점의 문안 검토

사용자가 직접 읽는 대신 검토·수정을 승인했다. 회사별 담당 범위와 대표 4개는 유지하고 원인·판단·수정의 반복을 줄였다. 판단은 왜 그 조치가 필요한지, 수정은 공통 원본의 실제 변경을 설명하도록 역할을 구분했다. 단위 테스트 4건이라는 작은 수치는 성과로 강조하지 않고 검증 시나리오와 당시 기록으로 설명한다.

당시 테스트 결과와 테스트 정의를 구분하고 운영 개선율·무재발·단독 구축을 추가하지 않았다. 구매 API의 비동기 이벤트 리스너 분리는 보류를 유지한다. 배치의 로그·DB 확인은 사용자가 확인한 경험이며 모니터링 구현·예정 시각 1시간 후 알림 조건은 이미 근거가 있어 다시 질문하지 않는다. 변경은 경력기술서 확장 설명에 한정하며 이력서 공통 사실과 웹 포트폴리오의 사실관계는 그대로 유지한다.

## Impeccable 디자인 정리 · 2026-10-03

사용자는 내용 유지와 impeccable 적용을 승인했다. Quiet Slate의 색·평평한 표면을 유지하고 회사 정보의 기간을 우측에 정렬했다. 업무 항목은 불필요한 불릿을 없애고 제목·설명을 같은 시작선에 놓았다. 사례 항목명을 좁은 열에 정렬해 문제·원인·판단·수정·검증을 훑어볼 수 있게 했다. 480px 이하에서는 항목명을 본문 위로 쌓는다. 사실 원본과 확장 설명은 수정하지 않았다.

A4 3쪽 렌더를 모두 확인했다. 본문·푸터 간 최소 간격은 약 36px이다. 390·768·1280px 화면에서 가로 넘침과 페이지 오류가 없었고 모바일 본문 16px, 메뉴 최소 높이 44px와 키보드 포커스를 확인했다. 디자인 detector는 anti-pattern 0건이다. 독립 문서의 pt 인쇄 규격 및 16px 모바일 본문 등은 사이트의 일반 타이포그래피와 별개인 의도된 문서 규격이며, 기존 선택 색상도 유지했다. 전체 사이트 디자인 체계를 변경하지 않았다.

기존 경력기술서는 PR #59 병합 후 Pages run 37101449104로 배포됐고 HTTP 200·이전 PDF 해시 일치를 확인했다. 위 출력 해시는 후속 디자인 PR 산출물이며 아직 배포된 새 파일로 간주하지 않는다. 기존 이력서 PDF는 재생성하지 않았다.
