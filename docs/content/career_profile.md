# 손찬양 경력 근거 프로필

기존 이력서·웹 콘텐츠와 공개 프로젝트 코드에서 확인한 정보를 정리한 작업용 문서입니다. B2B 리테일 교육 플랫폼의 업무 기록과 사용자가 제공한 회사 소스 사본을 대조해 실무 사례를 보강했습니다. 원문 코드와 내부 링크는 공개하지 않습니다. 최종 확인일: 2026-10-02.

## 1. 기본 정보

손찬양 / Son Chanyang. [GitHub](https://github.com/cyson21) · [포트폴리오](https://cyson21.github.io/).

## 2. 직무와 방향

Java·Spring Boot 백엔드 개발자. API 개발·운영, 데이터 정합성, 운영 문제 재현·수정·회귀 검증을 중심으로 소개한다. 관리직이나 아키텍처 총괄 경험을 추가하지 않는다.

## 3. 요약

2021년부터 백엔드 개발·운영 업무를 수행했다. 이엠캐스트에서 B2B 리테일 교육 플랫폼의 API, 버전 전환, 데이터 접근 계층과 운영 이슈를 담당했다. 화이트스캔에서 공공·실시간 데이터 수집·가공과 조회 API, DB 스키마, 예측 결과 연동 및 Docker 배포·운영을 담당했다. 개인 프로젝트의 분산 시스템·동시성·AI·CDC 구현은 회사 실무와 구분한다.

- B2B 리테일 교육 플랫폼 REST API 설계·개발·운영, 관리자 기능 개편 지원.
- 교육 플랫폼 2.0→3.0 전환 영향 점검, 회귀 검증, 레거시와 API·DB 구조 개선.
- 운영 장애·데이터 오류 재현·분석, API·DB 로직 수정, Testcontainers 통합·회귀 테스트.
- JPA·QueryDSL 조회·저장 구조 정리.
- AWS Lambda·CloudWatch·RDS·EC2·WAF 운영 참여, S3·SDK v2 사용 기록, Docker 배포·전환 이슈 대응.
- CI/CD 안정화와 코드리뷰에 참여. 파이프라인 전체를 구축·총괄했다고 쓰지 않는다.

### 화이트스캔

## 17. 이력서에 사용할 근거

실무는 API 설계·개발, 버전 전환, 운영 오류 분석·수정·회귀 검증, 데이터 파이프라인과 배포 참여를 중심으로 쓴다. 개인 프로젝트에서는 중복 이벤트, 종료 상태 변경 차단, 5회 발행 실패 처리, 동시 보상 8건 중 1건 반영, 잔액 100에서 60씩 두 번 차감 시 잔액 40, 수량 3개 쿠폰에 요청 8건 중 3건 발급, 문서 5건 중 허용 3건 검색 등 테스트 조건을 함께 제시한다.

대표 실무는 저장 시점 상태 재검증, 구매 API의 락 경합·커밋 경계, ShedLock·Redis 기반 배치 실행 제어, 복합 식별자 기반 조회·삭제·페이지 집계의 네 사례로 정리한다. 포트폴리오에는 Redisson 기반 Redis 만료 이벤트 제어를 추가한다. 시간대와 테스트 환경 일원화는 보조 근거로 보존한다. 상세 주장 경계는 [실무 사례 검토](work-case-review.md)에 기록했다.

## 18. 미확인 항목과 주장 한계

- 현재 재직 상태와 직급은 기존 기록을 유지했다. 최신 인사 정보는 별도로 확인해야 한다.
- 회사 성과의 개선율·처리량·사용자 수·비용 절감·장애 감소 수치는 확인되지 않았다.
- 팀·고객 수는 기존 기록이며 기준 시점이 없다.
- 경력 기간은 월 단위 기록이며 정확한 입·퇴사일, 공백, 중복 월은 확정하지 않았다.
- 테스트 코드의 assertion을 검토했으며 프로젝트 6개 전체를 이번 작업에서 다시 실행하지 않았다.
- 개인 프로젝트 설계 이유는 기존 설명과 코드 구조를 근거로 다듬었다. 새 인터뷰나 새로운 업무 경험을 만들지 않았다.

## 19. 표현 원칙

회사 실무 설명에는 수료 조건·진척률·차수·학습자 등 회사 도메인 용어를 사용하지 않는다. 처리 기준·작업 상태·설정 변경·예약 알림 등 범용적인 개발 용어로 원인과 수정 내용을 설명한다. 원본 업무 기록의 사실관계는 유지한다. 기존의 `참여`, `지원`, `연동`을 `총괄`, `단독 구축`, `모델 개발`로 확대하지 않는다. 결과 수치는 테스트 입력과 환경을 붙인다. 실무 경력과 개인 프로젝트를 같은 성과 목록으로 합치지 않는다.
