# 채용 자료 문안 정리 · 2026-10-30

이력서에서 운영 문제 해결 경험이 먼저 보이도록 소개문을 수정하고 기술을 분야별로 묶었다. 화이트스캔의 일정 관리·고객사 요구사항 확인·소통 주도는 사용자가 현재 지원 대화에서 직접 확인한 역할을 회사 요약에 반영했다. 프로젝트별 미확인 성과나 수치는 추가하지 않았다.

경력기술서 첫 장에서 이력서와 겹치는 도입부·정합성 요약을 줄이고 배치·구매 API의 수정 판단을 먼저 배치했다. 상세 상황·수행·검증과 한계는 둘째 장에 유지한다. 이력서와 경력기술서에 이미 공개된 이메일을 추가했다. 전화번호·연봉 등 비공개 인적사항은 공개 원본에 넣지 않았다.

포트폴리오 첫 화면은 실무 세 사례의 문제·수행·확인으로 구성하고 개인 프로젝트는 별도 링크로 안내한다. RabbitMQ 사례는 코드·완료 기록의 확인 범위를 표시하며 운영 성과로 확대하지 않았다.

검증: 정적 빌드, 공개 안전성(10개 자산), 내부 링크(14개 HTML) 통과. 첫 안전성 검사는 변경 HTML의 manifest 갱신 전 실패했고, 실제 파일 해시 갱신 뒤 안전성·링크 검사를 통과했다. PDF는 인앱 브라우저 Page.printToPDF로 기존 출력 템플릿에서 생성했다. 이력서 2쪽·경력기술서 3쪽을 렌더링해 전체 페이지를 확인했다. 본문과 푸터 간격은 이력서 최소 104px, 경력기술서 최소 122px. 390px 포트폴리오 가로 넘침 없음. 별도 합본은 5쪽과 이메일·소통 역할 텍스트 보존을 확인했다.

공개 배포·채용 사이트 파일 교체 전의 수정본이다. 기존 접수에 제출한 자료는 이번 변경으로 교체되지 않는다.

첫 CI 브라우저 검사에서는 이메일 링크가 없어야 한다는 기존 인쇄 이력서 조건 1건이 실패했다(211건 통과). 이번 변경의 독립 PDF 연락처 요구에 맞춰 `mailto` 목적지를 확인하도록 수정했다. 인앱 브라우저에서 이메일 링크 1개·정확한 목적지·이력서 2장을 확인했으며, 관련 CI 검사를 다시 실행한다.
