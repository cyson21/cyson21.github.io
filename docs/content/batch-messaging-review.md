# 배치·메시징 근거 추가 검토

검토일: 2026-10-03. 사용자 제공 로컬 회사 소스·커밋과 추가 답변을 대조했다. 회사 원문 코드·내부 URL·고객 정보는 공개하지 않는다. 회사 코드 실행이나 운영 조회는 수행하지 않았다.

- 배치: 예정 시간대별 스케줄러, 고객사·배치별 상태 집계, 실패·락 미획득·발행 누락·처리 결과 없음의 구분을 확인했다. 요약 시각은 예정 시각 1시간 뒤이며 정상 요약도 보낸다. 관련 테스트는 정의를 확인했으며 재실행하지 않았다.
- 담당·검증: 본인은 모니터링을 구현하고 서버 로그·DB 기록으로 실행 결과를 확인했다고 답했다. 당시 로그 원본을 이번 분석에서 확인한 것은 아니며 개선 수치를 추가하지 않는다.
- RabbitMQ: 동기 RPC를 비동기 요청 발행으로 바꾸고 별도 결과 큐에서 최종 이력을 전달한 변경을 확인했다. HTTP 202는 접수이며 최종 발송 성공이 아니다. 결과 큐 리스너에는 제한 재시도와 DLQ 설정이 있다.
- 범위: 채널별 발송 구현, 최종 DB 저장, 브로커 확인과 멱등성·DLQ 재처리·운영 결과는 별도 확인이 필요하다. 해당 변경 참여 경험을 유지하며 단독 구현이라고 확대하지 않는다. 병렬 발송·타임아웃 연장을 확인된 해결책으로 쓰지 않는다.

이력서 대표 4개는 유지하고 배치 관측을 보강한다. 포트폴리오는 RabbitMQ를 포함한 대표 5개로 구성한다. Redis 만료 이벤트는 기존 근거 문서에 보존한다. 지원 플랫폼 정본을 변경하거나 병합·배포하지 않는다.
