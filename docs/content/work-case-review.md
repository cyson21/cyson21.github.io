# 공개 실무 사례의 근거와 표현 범위

검토일: 2026-10-02. 업무 CSV와 사용자가 제공한 로컬 회사 소스·커밋 사본을 대조했다. 회사 원격 저장소 접속, 코드 실행, 운영 서비스 조회는 하지 않았다. 제출용 플랫폼 정본은 변경하지 않았다.

| 사례 | 확인한 구현 | 확인한 검증 근거 | 주장하지 않는 내용 |
|---|---|---|---|
| 저장 시점 상태 검증 | 변경 적용 전 상태 재조회·전이 차단·후속 갱신 기준 통일 | 정상·전이·기존 이력·입력 누락 테스트, 당시 단위 결과 기록 | 모든 동시성 경합의 원자적 방지, 전체 통합·운영 검증 완료 |
| 구매 API 락 경합 | 주문 락·별도 결제 트랜잭션·요청 상태 선행 커밋·제한 재시도·완료 상태 확인 | 테스트 정의, 초기 QA 문제와 후속 수정 기록 | 예상 PASS를 실제 성공으로 표현, 이벤트 리스너의 비동기 분리, 운영 재발률 |
| 배치 중복 실행 | ShedLock·Redis 설정과 여러 스케줄러의 락 적용 | 도입 diff, 본인의 분산락 적용 답변 | 다중 서버 실행 로그 확인, 장애 시 exactly-once, 전후 중복 횟수 |
| 복합 식별자 | 조회·삭제·동등성 조합 통일, DB 필터·페이지 집계 | 관련 테스트와 당시 검증 기록 | 이번 테스트 재실행, 전체 API 정합성·성능 수치 |
| Redis 만료 이벤트 | Redisson 실행기·키별 락·미획득 분기·보유 락 해제 | 관련 리스너 커밋과 테스트 정의 | 클라이언트 사용 불가 시 중복 없음, 이벤트 누락 복구 |

저장된 기록은 당시의 자료이며 이번 실행 결과와 구분한다. 테스트의 존재는 실행 통과를 의미하지 않는다. 구매 API의 초기 문서는 예상 결과와 QA 재검증 권고를 포함하므로 성공 증거로 사용하지 않았다.

메시징 RPC 타임아웃은 발송 서비스 구현이 없어 대표 이력서에서 보류했다. 병렬 처리·제한 시간 조정은 잠정 기억이며 최종 대응으로 쓰지 않는다. 후보 자료와 본인 답변은 별도로 보존한다.

수료 조건·차수·학습자 같은 회사 용어는 공개 사례에서 처리 기준·설정·사용자·작업 상태로 바꿨다. 회사 원문 코드, 내부 URL, 실제 일감 ID, 고객 정보는 복사하지 않았다. 팀·고객 규모는 기존 확인 범위를 유지하고 새로운 개선율·처리량·운영 무재발을 만들지 않았다.

웹 이력서와 PDF는 회사 경력과 실무 사례를 중심으로 구성하고 개인 프로젝트는 포트폴리오의 보조 자료로 연결한다. 사람인 네이티브 PDF의 기존 정본 지정과 스냅샷은 유지하며 채용 플랫폼 수정이나 공개 배포를 수행하지 않는다.
