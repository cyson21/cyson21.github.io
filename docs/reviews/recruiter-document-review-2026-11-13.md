# 두 지원 문서의 채용담당자 관점 검토

## 발견과 수정

- 경력기술서의 판단·수행·기여가 같은 조치를 세 번 설명했다. 담당 범위를 각 사례 머리에 밝히고 문제·해결 과정·변화로 통합했다. 판단 이유는 실제 수행 순서 안에서 설명한다.
- 이력서의 배치 집계 상세, 컬렉션 동등성 등은 경력기술서와 겹쳤다. 이력서는 문제와 주요 조치를 요약하고, 세부 집계 종류·분기·실행 순서는 경력기술서에 남겼다. 동일 사례의 제목·핵심 사실은 두 문서를 대조하는 데 필요해 유지했다.
- '페이지 집계를 맞췄다', '선행 커밋' 등 압축 표현은 목록과 총건수에 같은 필터 적용, 요청 상태를 먼저 커밋하는 순서로 풀었다.
- 이전 회사 소개에서 프로젝트 일정·고객 소통을 반복하던 부분을 줄였다. 시뮬레이터 설명은 기술 이름과 실제 구현 역할을 연결했다.
- 이력서 2쪽 하단의 큰 공백은 본문 11.5pt, 이전 프로젝트 간격과 줄 간격, 학력·관련 기술의 크기를 조정해 줄였다. 경력기술서는 본문 11pt와 넓어진 줄 간격을 사용한다. 설명을 추가해 지면을 채우지는 않았다.

## 확인

- 회사·기간·기여의 기존 사실을 유지했고 새 성과 수치를 추가하지 않았다. 개인 프로젝트는 이력서에 넣지 않았다.
- 두 PDF 모두 A4 2쪽. 최종 4쪽을 PNG로 렌더링해 글자·쪽 경계·여백·잘림을 확인했다.
- 출력 원본의 본문 끝과 footer 사이 간격은 이력서 약 80/132px, 경력기술서 약 78/96px이다(673px 폭, print 미디어). 이전 이력서 2쪽 약 354px에서 줄였다.
- 원본 390/994px 가로 넘침 없음. 관련 브라우저 검사 6개, 공개 안전성·내부 링크 검사 통과. PDF 텍스트 추출 확인.
- 공개 배포 뒤 실제 두 다운로드 버튼으로 받은 파일의 SHA-256과 쪽 수를 확인한다.
