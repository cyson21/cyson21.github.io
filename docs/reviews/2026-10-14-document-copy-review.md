# 이력서·경력기술서·포트폴리오 문구 검토 · 2026-10-14

문서의 역할과 기존 디자인을 유지하면서 추상적인 자기평가, 검토자 말투와 긴 명사 나열을 정리했다. 경력 사실은 `docs/content/career_profile.md`, 실무 사례의 한계는 기존 근거 검토 문서를 기준으로 대조했다. 회사 원본 자료에 새로 접근하거나 개인 프로젝트 전체를 재실행하지 않았다.

Member Event Consistency의 담당 범위 두 문자열은 화면용·스크린리더용이었다. 화면 중복으로 삭제하지 않고 접근성 구조를 유지했다. 툴팁과 스크린리더 문구의 날짜·역할 표기를 다듬고, 기존 검사는 전체 문장 고정 대신 툴팁·스크린리더 설명의 일치와 간결한 화면 표기를 검사하도록 변경했다.

## 유지·추가 확인 범위

- 회사·기간·직급·역할·4인 개발팀·20개 이상 기업 고객, 주요 기술과 검증된 테스트 조건을 유지했다.
- 실무 5개·개인 프로젝트 6개, 기존 앵커와 다운로드 경로, PDF의 URI 링크를 유지했다.
- 실무와 개인 구현, 테스트 정의와 실행 결과를 구분했다. 운영 개선율·처리량·무재발 성과를 추가하지 않았다.
- CI/CD의 구체적인 파이프라인 수정 내용은 기존 경력 근거에 없다. 새 작업을 추정하지 않고 참여 범위의 문구만 정리했다.
- Fashion 테스트 기준은 공개 `tests/test_batch_workflow.py`의 `snapshots_written >= 2`, `stale_snapshot_users == 0` 등과 기존 프로젝트 문안을 대조했다. 이번 작업에서 추천 프로젝트 테스트를 실행한 결과로 표현하지 않는다.

## 로컬 검수

- `pnpm install --frozen-lockfile`: 잠금 파일 변경 없이 설치.
- `node --test tests/unit/public-portfolio.test.mjs`: 9건 통과.
- `node --check tests/unit/public-portfolio.test.mjs`, `git diff --check`: 통과.
- `pnpm verify:local`: 정적 빌드·공개 안전성(승인 자산 10개)·내부 링크(HTML 14개) 통과. 소스 빌드는 한 번 수행했다.
- `pnpm generate:resume`, `pnpm generate:career`: 기존 인쇄 템플릿에서 각각 한 번 생성.
- `pdfinfo`·PDF 텍스트·URI 추출: A4 2쪽·3쪽, 기존 URI 링크 각 4개 유지.
- 렌더링한 PDF 5쪽과 변경 영역의 1280·390px 화면 확인. 본문·푸터 최소 간격은 이력서 107px, 경력기술서 197px. 가로 넘침·JavaScript 오류 없음.
- PDF SHA-256과 승인일 갱신 후 dist에 PDF만 복사하고 `pnpm test:privacy`, `pnpm test:links` 통과. 소스를 재빌드하지 않았다.

PR의 preview·release 검사와 병합 후 Pages 배포는 GitHub의 해당 커밋 실행 결과로 확인한다. 채용 사이트 등록본과 portfolio-hub의 과거 릴리스 첨부는 이번 변경 범위에 포함하지 않는다.
