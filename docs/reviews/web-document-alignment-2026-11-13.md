# 웹 포트폴리오와 지원 문서의 내용 정리

## 대조 기준

최신 이력서와 경력기술서의 경력 사실·담당 범위를 기준으로 홈, 경력, 실무 목록·상세, 개인 프로젝트 목록과 6개 상세를 확인했다. 회사 코드나 회사 테스트를 새로 확인하지 않았다.

## 변경

- 네 핵심 실무 사례는 `src/data/professional-case-narratives.json`의 동일한 제목·문제·담당 범위·해결 과정·변화를 웹 상세와 경력기술서 출력이 공유한다. 기존 경력기술서 문안의 이동 전후 일치를 확인했다.
- 웹의 강한 'DB 데드락' 단정, 역할을 '참여'로만 축약하던 결제 설명, 반복된 문제·원인 문단을 최신 문안으로 맞췄다. 실제 수행 내용과 해결 순서를 먼저 보여준다.
- 회사 테스트 재실행 여부와 운영 수치 미확인을 반복하던 설명은 실무 상세에서 제거했다. 메시징은 변경 참여 범위를 유지하며 HTTP 202 접수와 최종 발송 결과를 구분한다.
- 실무 목록의 제목·이동 목적지는 상세와 일치하도록 같은 데이터로 생성한다. 배치 도식의 독립된 4단계 두 흐름과 기존 앵커·이전 링크는 유지한다.
- 경력 페이지는 이전 회사 프로젝트를 이력서와 같은 순서로 표시한다. 일반 소개의 일정·고객 소통 반복은 덜고 해당 프로젝트의 담당 범위에 남겼다. 제출 PDF는 각각의 역할과 2쪽 분량을 안내한다.
- 홈에서는 문제 해결 설명과 겹치던 목록을 기능 개발·데이터 처리·버전 전환 요약으로 바꿨다.
- RAG의 긴 테스트 설명은 상세의 결과·범위에 남기고 목록·첫 문단은 구현 요약으로 줄였다. 과거 테스트 결과의 '이번에'는 점검 당시 기록임을 명시했다. 개인 프로젝트의 코드·테스트 링크와 검토일·결과 수치는 유지한다.

## 확인

- 관련 단위 검사 9개 통과. 새 내용 일치 검사는 기존 불일치로 실패하는 것을 먼저 확인하고, 공통 원문 적용 후 통과했다. 재생성의 반복 안정성과 배치 도식 보존도 확인했다.
- 11개 경로 × 390/994px 가로 넘침 없음. 실무 목록의 5개 실제 링크가 해당 앵커와 공통 제목·기여로 이동함을 확인했다. 배치·복합 식별자 상세 화면을 검수했다.
- 최종 정적 빌드·공개 안전성·내부 링크 통과. PDF 파일과 기존 문안은 유지했다.
- PR CI와 Pages 배포 후 공개 URL에서 같은 경로·실무 링크·PDF 다운로드를 확인한다.
