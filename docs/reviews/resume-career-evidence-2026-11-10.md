# 이력서·경력기술서 근거 대조 · 2026-11-10

공개 이력서 2쪽과 경력기술서 3쪽의 모든 본문을 확인했다. 두 문서는 회사 경력 중심이며 개인 프로젝트의 테스트 수치를 직접 기재하지 않는다. 공개 개인 프로젝트의 테스트를 회사 실무의 증거로 사용하지 않았다.

## 확인한 자료와 범위

- 회사 로컬 소스 사본의 구현·테스트 및 당시 검증 기록 25개 파일을 대조했다. 검토한 파일 경로와 SHA-256은 작업 폴더의 비공개 대조 목록에 보존했다. 회사 코드·내부 식별자·경로·URL은 공개 문서로 복사하지 않는다.
- 저장 시점 상태 재검증, 구매 API, 배치·집계, 복합 식별자 사례의 코드와 테스트가 실제로 무엇을 호출·검사하는지 확인했다. 당시 검증 JSON의 완료 표제와 실제 실행 필드를 따로 읽었다.
- 회사 테스트를 이번에 재실행하거나 회사 원격 저장소·운영 환경을 조회하지 않았다. 기존 기록의 명령·통과 표시는 당시 보고이며 원본 실행 로그를 이번에 새로 확보한 것은 아니다.
- RabbitMQ는 앞선 소스 대조 기록에서 확인된 참여·요청과 결과 처리 분리 범위를 유지했다. 이번에 최종 발송·브로커·DLQ 재처리의 새 실행 증거를 확보한 것으로 쓰지 않는다.
- 이전 회사 4개 프로젝트, 기간·직급·학력·팀과 고객 규모·인프라 및 협업은 기존 경력 자료·제출본·확인 답변의 범위에서 대조했다. 이전 회사의 원본 코드·운영 결과와 최신 인사·규모 수치를 독립 검증한 것으로 표현하지 않는다.

| AWS·CI/CD·협업·규모·학력 | 기존 경력 자료와 확인 답변에 근거. 테스트 코드만으로 소유권·운영 효과를 입증할 수 없음 | 참여·운영 담당 범위와 기존 사실 유지. 구축 총괄·기여율·최신 규모를 추가하지 않음 |

`src/data/site.ts`의 공통 사실과 `src/data/career-description.ts`의 상세·인쇄 문구를 함께 수정했다. 웹 경력 페이지와 두 PDF의 설명이 다시 갈라지지 않도록 같은 원본을 사용한다. 인쇄 템플릿과 페이지 구성은 유지했다. 작업용 경력 프로필의 과거 StockRush 실패 5회 표현도 최신 프로젝트 대조에 맞춰 정정했다.

## 출력·검증

- 정적 빌드 1회 후 두 PDF를 각각 1회 생성했다. PDF를 dist에 복사하고 자산 manifest의 해시·승인 날짜를 갱신했다.
- 이력서 A4 2쪽, 경력기술서 A4 3쪽. 전체 5쪽을 PNG로 렌더해 본문·제목·표·푸터의 잘림·겹침과 한글 표시를 확인했다.
- Poppler 추출 텍스트로 수정 문구를 대조하고 페이지 좌표 범위와 링크를 확인했다. 이력서 링크 5개, 경력기술서 링크 3개다.
- 회사 코드의 존재·테스트 정의 확인과 PDF·사이트 자체의 생성·검사를 혼동하지 않는다. 사이트 CI 통과는 회사 서비스 테스트 통과의 증거가 아니다.
